# v1.8 结局封面与逐次游玩档案

完成一局后，结算页采用该主结局的专属场景，提供“查看本次数值曲线”。结局图鉴为已解锁结果显示对应封面，打开后可在多次达成记录之间切换；每次记录分别保留当时的结局文本、附加后果、政策记录、九项指标逐次变化和年度手记。

## 留存与查阅

- 通关时按当前周目的持久编号保存独立快照。刷新或重复渲染同一结局不会重复归档；再次通关同一结局会新增记录。
- 新游戏只替换进行中的进度，不删除已经归档的通关。查看历史不会恢复历史状态，也不影响当前游玩的资源与进度。
- 曲线、逐条事件、完整数值表与新年手记使用同一份当次统计。当前国家统计和历史曲线具有独立的选择状态与控件标识。
- 曲线横轴仍按实际事件顺序排列，避免把没有结算的年份画成虚构变化。年份标签按实际距离排布，减少手机端重叠。
- 档案存储在当前浏览器的`r56sov.runs.v1`中；原有解锁键与进行中的存档键继续保留。不会自动清理旧通关来腾空间。
- 支持导出全部档案、导出单次记录，以及导入JSON备份。导入先校验格式、指标和终值，再按编号合并；重复记录跳过，内容冲突或不完整备份不覆盖原数据。
- 不同设备、GitHub Pages与GPT网页作品属于不同浏览器存储空间，可通过导出／导入转移。清除网站数据会删除本地记录。
- 浏览器拒绝写入时，页面明确提示尚未保存；本次记录暂留当前页面内存，可导出备份，不会宣称已经持久保存。

旧版图鉴只有“已解锁”标志，最近一局统计没有可核实的主结局对应关系。因此保留旧解锁与新封面，并明确说明无法还原当时曲线，不将最近一局的数据错误套到所有结局。更新后的每次通关自动留存。

## 验证

`tests/endings.cjs`对24条路线逐一核对归档终值、年度统计和结局对应；覆盖独立副本、重复结算、备份合并、无效数据、旧解锁与实际存储失败。

`npm run test:browser:endings`通过文件选择器导入完整路线档案，检查同一结局的多次记录、九项终值、事件滑块、21年手记、刷新保留、实际下载文件在另一浏览器档案恢复、与当前进度隔离及旧版提示。320、390、768、1024、1440px检查图鉴与详情布局、图片解码和横向溢出。证据在`docs/qa/endings/`。

全路线浏览器测试还通过真实游戏按钮完成24局，检查每局自动归档、14种结局封面，以及所有原有250项目标。线上同一套验收由GitHub Actions运行。

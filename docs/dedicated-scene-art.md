## 画面与人物

采用低饱和自然色、炭黑阴影、暖纸色高光和少量暗红，与页面配色协调。根据文字设计会议、走廊、实验、生产、农庄、交通、城市、前线和普通生活的具体场景；拍摄距离、角度、人物动作和空间安排随情节改变。

历史人物使用明确的外貌锚点。虚构工人安娜的界面肖像与新场景中的同一人物对齐。玩家所处的最高领导人尽量保持在镜头之外，避免继承后仍在画面中出现斯大林。战争图片按实际评级选择，崩溃与失守不再共图；同一战区的不同战术也分别配图。

人工查看生成结果后修正构图中的小画中画、行进方向、年代不符的军装，以及出现在1930年代或1946年的战后高楼、预制板住宅等问题。四幅档案式静物画面通过法律草案、材料送达、日期核验和空会议室表达对应情节。

## 页面

新场景保持完整3:2比例，避免把人物和行动主体裁掉。大屏图像可突破760px正文列，最大约1040px；手机图片比正文更接近屏幕两侧，同时保留安全边距。图像先于会谈中的短消息显示，正文和选择按钮维持原有阅读宽度。

完整版本使用119份2×2图版传输473幅独立照片，每格为一幅完整构图，正常画面只显示与当前场景绑定的一格。图版按照当前页面加载，连续场景可以利用浏览器缓存；不同场景不共享同一照片。

## 数据与核对

- `scene-art-manifest.js`保存场景ID、源文件和独立图格。每个“文件＋图格”组合只分配给一个叙事画面。
- `scene-art.js`只负责只读渲染。旧存档和旧战报通过原场景ID、选项及战果推导图片，不改写资源与结算。
- `docs/scene-art/inventory.json`保留文字依据；`batches.json`和逐批审核记录保留来源与对应关系。`scripts/scene-art-prompt.cjs`记录生成提示与人物锚点。
- [图像目录](scene-art/catalog.html)可以按标题、人物、地点和场景ID搜索，区分已完成、待生成和待修正，供逐图检查。
- `docs/scene-art/pending.json`汇总待补图版、场景、提示和已知修正问题，当前清单为空，供今后扩展时核对。

运行`npm run audit:scene-art`核对资源完整性、原生尺寸、图片文件哈希、唯一图格以及审核记录。`node scripts/build-scene-manifest.cjs`与`node scripts/build-scene-catalog.cjs`可重新生成绑定和目录。
